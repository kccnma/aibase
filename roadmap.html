Design Principles & Roadmap

A proposed, incremental direction for evolving this static front-end starter.

Principles

  • Keep the base lightweight. Pages remain static HTML, CSS, and JavaScript, with no required build step or runtime dependencies.
  • Start with the platform. Prefer semantic HTML, native browser features, and CSS over custom JavaScript behavior.
  • Make accessibility and responsiveness part of the feature. Keyboard access, useful semantics, visible focus, and small-screen behavior are requirements, not later polish.
  • Build small vertical slices. Each change should deliver a usable behavior or pattern that can be reviewed and verified independently.
  • Use TDD. Define expected behavior and add a focused failing check before implementation; then implement the smallest change and rerun the check.
  • Document what ships. Update the docs and style-guide example with each feature so the starter stays understandable and usable.

Proposed roadmap

  1. Foundations and agreements

    Agree on these principles and document how contributors should work. This roadmap and AGENTS.md establish the initial proposal; they do not represent completed feature work.

  2. Optional browser checks and mobile navigation

    The first tracer bullet uses an optional Playwright browser-testing workflow, kept in development tooling and out of the site's published runtime, to verify the responsive, accessible site navigation across viewports and keyboard interaction.

  3. Complementary CSS layout patterns

    Add documented, responsive stack, cluster, split, and sidebar patterns where they solve layout needs not already covered by the existing grid. Keep each pattern focused and avoid creating a competing grid system.

  4. Essential content and form components

    Add accessible form controls and their states, cards, callouts, and native disclosures using semantic HTML where suitable. Include focused checks and practical examples in the docs and style guide for each component.

  5. Defer heavier JavaScript interactions

    Do not add tabs, carousels, or custom dropdowns just to expand the starter. Revisit them only when a concrete use case justifies the behavior, accessibility requirements, testing cost, and documentation.

Working agreement for each feature

  1. Describe the user-facing behavior and accessibility expectations.
  2. Add a focused failing test or check for that behavior before changing implementation.
  3. Implement the smallest complete vertical slice using existing conventions.
  4. Run the relevant checks, then update the docs and style-guide example alongside the feature.
  5. Review the code and documentation together; record any unresolved decision as a proposal.

The optional test runner is Playwright. Follow the setup and commands in the navigation documentation; these checks are not a prerequisite for using the starter.

AI Base

AI Base is a basic set of starter HTML, CSS, and Javascript created by a human, assisted by AI, and built for front-end developers and UX/UI designers that want to embrace AI to build custom static websites that are fast and accessible.
